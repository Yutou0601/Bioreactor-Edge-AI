### 執行內容如下所示：

**1. 實驗協定定案與現場運轉數值確認**

依與洪博討論定案之實驗協定：洗管線至基準值（甲烷 9.00%、二氧化碳 21.00%、壓力 1.185 kg/cm²）後進氣，以每小時循環 n 分鐘運轉（第 1–2 天 n=1、第 3–4 天 n=5、第 5–6 天 n=10），反應槽壓力降至下限 0.90 kg/cm² 時自動補氣至約 1.185 kg/cm²（設定上限 1.20，實際充填略低於整數值），約 20 小時補氣一次、48 小時內約三次，期滿排氣並洗管線回基準值後更換下一個 n 水準。

比對現場控制系統實際讀數（2026/07/22 14:48）確認運轉狀態：反應槽壓力 1.18 kg/cm²（數位表 1.179）、氣體混合槽壓力 3.05 kg/cm²、二氧化碳濃度 20.4%、甲烷濃度 9.04%、pH 7.01、ORP −502 mV。各項均落於基準值附近，確認系統已洗至基準並完成初次進氣；ORP 呈現大幅負值係新鮮氫氣注入後之強還原狀態，與先前分析所得「進氣瞬間 ORP 急降」之機制一致。另確認 HMI 面板之「反應槽壓力／混合槽壓力」標示與實際量測對象相符，先前發現之欄位對調僅存在於資料記錄層，非面板顯示問題。

HMI 溫度欄位顯示 0.0°C 一節，經確認為該顯示欄位未接線所致，實際溫度穩定於 30°C 且正常寫入 CSV，溫度屬受控變因，不影響後續分析。

**2. 實驗設計嚴謹性評估（菌群成熟度與控制因子共線問題）**

針對本協定可否產出可用於建模之乾淨特徵進行評估，結論為「循環週期內之特徵可用，但跨 n 水準之比較存在結構性混淆」。

可用之部分：洗管線至固定基準值之設計，使各 n 水準均自相同氣相狀態起始，消除了歷史資料「起始條件不一致」之混淆；每次進氣至下次進氣之循環週期內，壓力下降速率、ORP 崩落與恢復、pH 斜率等特徵均由可信訊號計算，乾淨且可重現。

結構性缺陷：控制因子 n 與實驗天數完全共線（n=1 於第 1–2 天、n=5 於第 3–4 天、n=10 於第 5–6 天），而菌群於此六日期間持續成熟。依先前歷史資料分析，菌群成熟度會主導壓力下降速率（快慢兩群之分野與 ORP 相關、2026-03-20 與 04-07 兩次體制轉換），故若觀察到 n=10 之下降速率高於 n=1，將無法區分係循環時間增加所致抑或菌群成熟四日所致。須留意洗管線僅重置氣相、不重置生物相，菌群狀態於各水準間仍持續漂移。另各 n 水準僅執行一次 48 小時實驗，其內約三次循環屬同一菌群狀態下之重複測量，非獨立重複，對跨 n 比較之統計檢定力低於原先假設。

補救方向提出三項，並經確認採行第一項：（一）由系統自動記錄每次補氣前之 ORP 作為菌群成熟度代理共變數，事後分析時據以扣除菌群漂移，成本為零且不更動實驗排程；（二）於各日穿插固定之參考 n 水準以追蹤漂移曲線；（三）打亂 n 之執行順序使菌群年齡不與 n 對齊。第二、三項涉及實驗排程調整，留待與洪博討論。

**3. 實驗批次管理功能改版以符合新協定**

重寫 `edge_backend/core/experiment_store.py` 之批次資料模型，使其對應新協定之實際運作方式：每個批次代表一個 n 水準之 48 小時實驗（而非單一注氣週期），期間包含數次自動補氣。新增欄位包括基準值（甲烷／二氧化碳／壓力）、自動補氣上下限、預計實驗時長，以及可預先指定之開始時間。批次生命週期改為三段狀態（已規劃→進行中→已完成），以符合「多個批次先行規劃、之後分日依序執行」之實務流程。

新增 `compute_cycles()` 函式，自批次時間窗內之壓力訊號自動偵測補氣事件（壓力單步跳升），將 48 小時切分為各次補氣之間的循環週期，逐週期計算下降壓力速率、進氣前 ORP 與 ORP 崩落深度，作為建模用之每循環特徵表。前端 `ExperimentView.vue` 對應改版，加入基準值輸入、開始時間指定、即時面板（目前壓力／ORP、距下次補氣預估時間、實驗進度）與每循環明細展開，並新增「每循環特徵」之匯出層級（每列為一個補氣循環，供建模使用），與原有之批次彙整報表並列。

另新增批次落地儲存機制：批次設定與起訖時間以原子寫入方式存至 JSON 檔，後端重啟時自動還原，避免因重啟導致已規劃之批次消失；量測結果仍由感測資料即時重算，不落地儲存。

**4. 系統缺陷修正**

開發過程中發現並修正三項缺陷：

其一，循環週期切分錯誤。原實作將「補氣至下次補氣」整段（含末端之壓力跳升）視為一個週期，導致週期起訖壓力相同、下降速率計算為零。修正為僅取補氣後高點至下次補氣前低點之下降段，驗證後計算值由 0 修正為 0.01462，與模擬輸入之 0.0146 相符。

其二，時間格式不相容。前端日期時間元件送出之格式為 `2026-07-22T14:30`（T 分隔、無秒），與感測器時間戳 `YYYY-MM-DD HH:MM:SS` 不同；因兩者以字串比較過濾資料，而 `T` 之字碼大於空格，導致指定之開始時間恆大於所有資料時間戳，一筆資料亦無法比對到。此缺陷使「指定過去時間開始」功能完全失效，即實驗已進行中才建立批次時，無法納入先前已收集之資料。新增時間正規化函式並套用於所有時間輸入欄位後修正，驗證確認可正確納入既有資料。

其三，排氣端點未接收指定時間參數。前端傳送之排氣時刻遭忽略、恆以當下時間為準，使人工指定排氣時間之功能無效。補上參數接收後驗證正常（指定 2.5 小時處排氣，計算總時長 2.48 小時）。

另依實務操作需求，將排氣改為人工輸入時間（預設當下、可修改為實際排氣時刻，或往後數分鐘以涵蓋甲烷峰值），並新增起訖時間之事後編輯功能，以利與 CSV 記錄對齊或修正誤操作。

**5. ORP 訊號正負號疑慮之釐清**

現場 ORP 控制器顯示為負值（−502 mV），而系統記錄與歷史 CSV 之 ORP 均為正值（範圍 235～687 mV，負值 0 筆），兩者存在落差，須確認記錄是否與實際相反，否則先前所有 ORP 分析之方向將全部顛倒。

查核結果：軟體端未對 ORP 施加任何正負號或偏移處理（直接讀取欄位後僅做指數移動平均平滑），落差來自上游記錄端。進一步判定該落差為常數偏移而非正負號翻轉，判定依據為方向一致性——CSV 中進氣當下 ORP 呈現下降（如 2026-04-07 09:24 由約 550 降至 382）而後回升，與控制器「進氣時降至 −502、隨後回升」之方向相同；若為正負號翻轉，CSV 於進氣時應呈現上升。推估真實電極讀數應位於負值區間（產甲烷環境屬強還原），記錄端加上約 +737 之常數偏移後成為正值。

由於常數偏移不改變相對變化之方向，先前所有 ORP 方向性結論均維持有效，包含進氣時 ORP 急降（17σ）及以恢復後高點作為菌群成熟度共變數之設計（該值為高值，遠離低端截斷）。惟需註記：部分資料出現 ORP 為 0 之情形，研判為深度崩落遭下限截斷，故「ORP 崩落最低點」此一次要特徵在極深崩落時不可信，主要指標不受影響。

**6. 每循環特徵擴充（菌群共變數與斜率平緩化）**

依第 2 項評估結論，於每循環特徵中加入「進氣前 ORP」作為菌群成熟度共變數。該值取自本次補氣前一筆之 ORP（即上一循環末、氫氣已耗盡、ORP 已恢復之高點），全程由系統自動計算，操作人無須填寫；批次層另彙整首末次補氣之差值作為菌群漂移指標。以模擬漂移資料驗證確認可正確捕捉（週期 2 為 545、週期 3 為 555，漂移值 +10）。

另依洪博提出之機制——產出甲烷時甲烷累積稀釋頭空二氧化碳，降低溶解驅動力，使壓力下降斜率趨於平緩——新增「斜率平緩化」特徵：分別計算週期早段與晚段之下降速率，其差值大於零即代表曲線先陡後平，為產甲烷之間接跡象。以模擬先陡後平之下降曲線驗證確認（早段 0.0161、晚段 0.0101、平緩化 +0.0060）。

須註記此特徵之限制：斜率平緩化亦可能來自純物理溶解趨近飽和，單獨觀察無法區分生物或物理成因；須搭配進氣前 ORP 共變數，檢視平緩化程度是否隨菌群狀態變動，方具分離能力。此設計之價值在於完全不依賴不可信之二氧化碳／甲烷感測器，即可取得生物活性之間接指標。

**7. 監控電腦自動更新中斷記錄之處置與分析程式補強**

監控電腦於當日 18:30 執行系統自動更新，導致記錄程式中斷。經回放確認中斷前已完成一次完整之補氣循環。

初步評估認為反應槽之自動補氣與循環係由控制器獨立執行，與監控電腦無關，實驗於物理上並未中斷、僅資料記錄中斷，故可延長本水準運轉時間補回損失之循環，毋須重跑。惟進一步檢視後推翻此判斷，改採重跑，理由為本協定之核心設計價值在於「各 n 水準均自相同氣相基準起跑」，此係消除歷史資料「起始條件不一致」混淆之唯一依據；自斷線至隔日恢復約 17.5 小時期間，反應器持續運轉並自動補氣，頭空組成已漂移至未知狀態，若接續運轉，該水準將形成前半段自基準起跑、後半段自未知狀態起跑之混合資料，與其餘 n 水準不可比，等同將原欲消除之混淆重新引入。以兩日排程換取實驗設計核心性質，不符成本效益。

中斷前已取得之完整循環仍為有效資料，應保留而非捨棄：該循環為 n=1、菌齡第 0 日、自乾淨基準起跑之合法觀測；重跑之 n=1 則為菌齡第 2 日。兩者構成「n 相同、菌齡不同」之對照點，恰可在控制因子固定之情況下單獨估計菌群成熟對下降速率之貢獻，為第 2 項所述補救方向二（穿插參考水準以追蹤漂移曲線）之一個實際樣本。此為原排程未能提供之資訊。

另檢視分析程式對此情境之處理是否正確，發現一項嚴重缺陷並修正。原實作僅以「壓力跳升」判定補氣、據以切分循環，未考慮記錄中斷；而中斷期間反應器仍在運轉並自動補氣，該次補氣未被記錄，導致中斷前後之兩段下降被黏成同一個循環。以模擬資料（中斷 14 小時、期間補氣一次）驗證，該循環之時長由實際 8.3 小時被誤計為 28.98 小時、下降速率由 0.0146 被低估為 0.00628（偏差 2.3 倍），且因晚段橫跨空窗而算出斜率平緩化 +0.01122——即**憑空產生一個「產甲烷」訊號**，而該值正是本研究欲量測之指標，於匯出報表上與真實數值無從分辨。

修正方式為於記錄中斷處一併切段（相鄰兩筆間隔超過 5 分鐘即判定中斷），使每一段均為「連續記錄且中間無補氣」之純下降段，並對每個循環標記資料完整性（完整／記錄中斷／起點未觀測／進行中）。僅起訖兩端補氣均被實際觀測到之完整循環，方計算斜率平緩化並納入速率中位數與建模；殘段之下降速率仍為有效值故予保留，惟明確標記。修正後重跑同一組模擬資料，三段速率均回復為真值 0.0146、假平緩化消失；另以乾淨資料驗證真實之先陡後平仍可正確測得（早段 0.020、晚段 0.010、平緩化 0.010）。同時修正兩項相關問題：斜率早晚段之切分改以時間中點取代索引中點（記錄有缺漏時兩者不一致），首個循環之「進氣前 ORP」原誤取進氣後之崩落值，現改為留空。

批次報表與前端每循環明細均增列資料完整性欄位，批次層另顯示記錄中斷次數與合計時數，使資料可用程度於報表上為明示而非需自行察覺。經此修正，中斷區段可由系統自動辨識，毋須再以人工切分批次規避。
