**3.「丟 CSV → 每段下降報表」功能開發與驗收**

依會議需求開發，位於前端 `/descent` 頁：丟入 CSV → 切出每段壓力下降 →
回報**總下降、平均下降速率、最小平方斜率與 R²**，並可再細分為固定長度視窗。

實作於 `edge_backend/core/descent_report.py`，純 numpy 閉式計算，不引入任何
重量級套件（常駐核心記憶體預算 60 MB）。

**驗收條件**（沿用生物速率搬移時的標準：跑得動不等於算對了）：化學計量
必須重現既有 `batch_rates.py` 的已發表數字。批次 2 之 CH4 分壓 0.52280、
批次 3 之 0.67380，**逐位元相同**。

換算方式全程走**壓力單位**而非莫耳。Sabatier 反應 CO2 + 4H2 → CH4 + 2H2O(液)
在氣相淨少 4 mol、產生 1 mol CH4，故

> CH4 產量 / 總壓降 ≤ 1/4 = 0.25，生物份額 = 該比值 ÷ 0.25

分子分母同為該頭空之分壓，**容器體積自動消掉**——計算生物份額不需要知道
1.99 L。體積僅在需要「絕對莫耳數」時才用得到。

**4. 切段門檻與自動化設定不相容（本日最重要之發現）**

以現行分析門檻（振幅 ≥ 0.10 kg/cm²、時長 ≥ 4 hr）處理這 20 天資料，
**僅切出 3 段**；先前 33 天的資料則可切出 46 段。

原因並非資料品質，而是**自動化把循環壓得太短太淺**：

- 不套門檻時可切出 263 段，其中 246 段有淨下降
- 振幅中位 **0.050 kg/cm²**（四分位 0.040 ~ 0.070）——僅約 **5 個量化階**
- 時長中位 **1.95 hr**（四分位 1.67 ~ 2.02）
- 通過現行門檻者僅 **1.2%**

亦即自動化每約 2 小時補氣一次、每次只讓壓力掉 0.05，而分析要求振幅 0.10、
時長 4 小時，兩者不相容。**這正是會議提出「3–4 hr 排一次氣」的正確方向**：
把循環拉長，振幅才夠大、量化雜訊佔比才夠小。

另一項相關量測：感測器量化階為 0.01 kg/cm²，而典型下降速率中位 0.033
kg/cm²/hr，故

| 視窗 | 中位 ΔP | 完全沒有變化的比例 |
|---|---:|---:|
| **10 分** | **0.0000** | **59%** |
| 30 分 | 0.0100 | 37% |
| 60 分 | 0.0100 | 21% |
| **180 分** | **0.0600** | **3%** |

會議所提「先算 10 min」在本感測器上**六成視窗壓力一個數字都沒有動**，
所得斜率為量化雜訊而非速率。功能預設視窗改為 180 分鐘（即會議規劃的
3–4 hr 排氣節奏），低於分辨力之視窗於介面標示「量不到」而非顯示「斜率 0」
——後者會讓人誤判為反應停止。

**5. CH4 濃度錨點不足之量化**

會議希望「從每一段的 CH4 反推 CO2」。以既有 33 天資料實測：

- 壓力切出 46 段，但**整段期間僅偵測到 5 個 CH4 排氣尖峰**
- 尖峰落在段內者僅 **2 段（4%）**
- CH4 讀數中位 0.55%，尖峰值 14.6 ~ 50.1%（相差兩個數量級）

直接以每段頭尾的 CH4 反推，**46 段全部**算出負的生物份額——產甲烷不會
讓 CH4 分壓下降，那些讀數是管路拖尾而非頭空組成。此即「自動化不太穩定」
之量化原因：**錨點數就是樣本數**。

故另實作「排氣錨點之間」分析：以 CH4 尖峰為錨點，計算相鄰兩次排氣之間
轉換掉多少氣體。消耗量採**區間內各下降段之壓降總和**，而非頭尾相減
（中間有補氣，頭尾相減會把補進來的氣體算成未被消耗，份額虛高）。

實測第一個區間：

```
2026-07-03 → 07-13   235 hr   12 段下降
   CH4 14.55% → 50.14%      消耗總計 3.850 kg/cm²
   CH4/消耗 = 0.1648（上限 0.25） → 生物份額 66%
   用掉 CO2 0.635、H2 2.538 kg/cm²
```

該比值 0.1648 與既有批次紀錄之 0.168 相符，可作為交叉印證。

## 需求規格（依 2026-09-11 會議紀錄整理）

### 目標

量化「一段時間內有多少 CO2／H2 被轉換為 CH4」，並將排氣頻率提高到
3–4 小時一次以取得足夠的濃度錨點。

### 設備與量測前提

| 項目 | 值 | 來源／狀態 |
|---|---|---|
| 取樣頻率 | 1 筆／分鐘 | 已核對，實測中位間隔 1.00 分 |
| 壓力量化階 | 0.01 kg/cm² | 實測 |
| 容器**總**容積 | 1.99 L | 已確認（2026-09-11） |
| **頭空**體積 | **約 1.00 L** | 由兩支壓力計反推，n=71，見下方補充一 |
| 大氣壓 | 1.033 kg/cm² | P_abs = P_gauge + 1.033 |
| 起始絕對壓 | 1.2 + 1.033 = 2.233 kg/cm² | 會議提供 |
| 排氣量 | 自 1.1 排掉 0.16 kg/cm² | 該量足以將分析儀沖出真正的 CH4 最高值 |

### 運轉規格（待驗證）

1. 反應器自 1.2 kg/cm² 開始，任其下降至約 1.1 kg/cm²
2. 每 3–4 小時排氣一次，每次排掉 0.16 kg/cm²
3. 排氣當下記錄 CH4 濃度最高值（此為唯一可用的濃度錨點）
4. 以 1 hr / 2 hr / 3 hr 三種間隔比較可轉換氣體量

### 計算規格（已實作）

```
消耗量      = 該區間內各下降段之壓降總和（不是頭尾相減）
CH4 分壓    = CH4 濃度 × 絕對壓
CH4 產量    = 期末 CH4 分壓 − 期初 CH4 分壓
CH4/消耗    ≤ 0.25                      （CO2 + 4H2 → CH4 + 2H2O）
生物份額    = (CH4/消耗) ÷ 0.25
CO2 消耗    = CH4 產量                  （莫耳比 1:1）
H2  消耗    = 4 × CH4 產量
絕對莫耳數  = ΔP·V/(R·T)                （僅此項需要體積）
```

### 驗收條件

- 化學計量須重現既有 `batch_rates.py` 之數字（已達成，逐位元相同）
- 生物份額落在 0 ~ 100% 之外者一律標為不可用，不顯示數值
- 低於感測器分辨力之視窗須標示「量不到」，不得顯示為 0

### 四、排氣 0.16 kg/cm² 為自動執行（已確認）

自動執行代表排氣時刻由控制器決定、可重現，這對錨點是有利的。但**取樣頻率
才是限制**：

- 實測 223 次補氣事件中，**94% 在單一取樣點內即完成**（≤ 1 分鐘）
- 補氣一分鐘內即抬升 0.050 kg/cm²
- 若排氣速率相當，排掉 0.16 kg/cm² 約需 **3.2 分鐘**，即落在 **3 ~ 4 筆**資料上

3 ~ 4 筆足以捕捉到 CH4 尖峰，但餘裕很小，且尚未計入分析儀本身的響應延遲
（氣體需流經管路才到達感測器）。

> **建議**：擇一執行——(a) 排氣期間提高取樣頻率（例如每 10 秒一筆），
> 或 (b) 放慢排氣速度使其橫跨 10 分鐘以上。前者較不影響製程。
