# 遠端存取：架構與工程師連線說明

2026-10-14 建置並實測；2026-10-16 依**架構 B** 改寫（後端、資料庫、網頁搬到 Jetson，
監控電腦只跑記錄程式與上傳程式，見 `監控電腦部署流程_架構B_2026-10-16.md`）。給兩種人看：

- **工程師**：在家或任何地方，連 Jetson 改模組、看網頁；必要時連監控電腦看檔案。看 §2、§3。
- **管理者**：加人、（選配）讓監控電腦可被 SSH、出事時救回來。看 §4、§5。

密碼、通行碼一律不寫在這份文件裡（repo 會上 GitHub），另行告知。

---

## 1. 架構

```
工程師電腦（任何地方）
   │  Tailscale（加密私網；不對公網開任何埠）
   ▼
Jetson Orin NX  mirdc-orin-nx        ← 唯一連外網的機器
   ├─ 網頁＋API :8000（後端、資料庫、分析都在這台）
   │     只接受本機、USB、Tailscale 來源（REACTOR_ALLOW_NETS）＋防火牆
   ├─ SSH 只收金鑰；防火牆只放行 USB／有線／Tailscale
   │  USB（192.168.55.x）
   ▼
監控電腦（Windows，不連外網）
   ├─ 記錄程式 → CSV → 上傳程式（只往外連 Jetson，不開任何入站埠）
   └─（選配，§4.2）SSH：只收金鑰、只接受來自 Jetson 的連線
```

**工程師看網頁**：經 Tailscale 直接開 `http://mirdc-orin-nx:8000`，不必再走 SSH 通道。

⚠ **API 對 Tailscale 網段整段開放，而它沒有登入驗證**（只有上傳要通行碼）。也就是說，
**加進這個 Tailscale 網路的每一台裝置都能使用刪除類功能**。所以 Tailscale 網路裡只放
信任的人，人離開就移除（§4.1）。

**為什麼監控電腦不開網頁、只（選配）開 SSH**：監控電腦上已經沒有後端；它唯一需要被
連進來的理由是「遠端看它的檔案或記錄程式」，SSH 一個埠就夠，而且只收金鑰。

**為什麼不用 Windows 檔案分享（SMB）**：那是勒索病毒的主要傳播途徑，正是實驗室
顧慮的事。

### 實測結果（2026-10-14，架構 A 時期）

以下是改成架構 B 之前測的。Tailscale、Jetson SSH、跳板到監控電腦、取 CSV 這幾項
與架構無關，結果仍適用；「經 SSH 通道看監控網頁」那項在架構 B 已不需要。

| 路徑 | 結果 |
|---|---|
| 工程師 → Jetson（Tailscale，金鑰） | ✓ |
| 工程師 → Jetson（密碼） | 拒絕（設計如此） |
| 從同一 Wi-Fi 內網直連 Jetson :22 / :8100 | 防火牆擋 |
| Jetson → 監控電腦 SSH（Jetson 專屬金鑰） | ✓ |
| 從 Wi-Fi 那一側連監控電腦 :22 | 防火牆擋 |
| 工程師 → Jetson → 監控電腦（SSH 跳板） | ✓ |
| 工程師看監控網頁（SSH 通道 → `localhost:18000`） | ✓ API 與首頁皆 200 |
| Jetson 直接打監控電腦 :8000 | 連不到（修正前是 **200**，見 §6） |
| 遠端改 Jetson 模組 → 重啟 → 由監控端觸發 → 跑到改過的版本 | ✓ |
| Jetson 從監控電腦取 CSV（`scp -O -T`） | ✓ |
| Jetson 以 sftp 瀏覽監控電腦 | ✗ 尚未解決，見 §6 |

跨網際網路：10/15 以手機熱點上的筆電實測可用（見 10/16 日報第 8 點）。

## 2. 工程師第一次設定

1. **安裝 Tailscale**（tailscale.com/download），用管理者邀請你的帳號登入。
2. **產生 SSH 金鑰**（已有就跳過），把**公鑰**（`.pub`）傳給管理者：
   ```
   ssh-keygen -t ed25519 -C "你的名字"
   ```
   ⚠ 只傳 `.pub`，私鑰永遠不離開你的電腦。
3. 管理者把公鑰加到 Jetson 後（§4.1），在你的 `~/.ssh/config` 加：
   ```
   Host jetson
       HostName mirdc-orin-nx
       User jetson
       ServerAliveInterval 30

   # 選配：監控電腦有開 SSH（§4.2）且你的公鑰也加到那邊時才有用
   Host monitor
       HostName 192.168.55.100          # 監控電腦在 Jetson 那一側的位址
       User "<監控電腦的 Windows 帳號>"   # 帳號有空格要加引號
       ProxyJump jetson
       ServerAliveInterval 30
   ```
4. 測試：`ssh jetson` 要能直接登入、不問密碼；瀏覽器開 `http://mirdc-orin-nx:8000`
   要看到監控網頁。

## 3. 日常操作

### 3.1 改 Jetson 上的模組

建議用 **VS Code ＋ Remote-SSH**：連 `jetson`，開資料夾
`/home/jetson/Bioreactor-Edge-AI/edge_backend/modules/`。

Jetson 上有兩個服務：`reactor-compute`（分析模組，:8100）與 `reactor-web`（後端、
資料庫、網頁，:8000）。下面這些指令不需要 sudo 密碼：

```bash
sudo systemctl restart reactor-compute           # 改了 modules/ 底下的計算
sudo systemctl restart reactor-web               # 改了後端（api/、core/、main.py）
sudo systemctl status reactor-compute            # 確認 active（reactor-web 同理）
sudo journalctl -u reactor-compute -n 50         # 看載入有沒有錯
curl -s localhost:8100/health                    # 模組都要是 ready
```

⚠ **改到 `module.json` 的 `result_columns`、或 `run.py` 的 `SCHEMA` 時，兩個服務都要
重啟。** 結果表由 `reactor-web` 依 `module.json` 建立；只重啟 compute 的話，畫面只會
顯示「結果是舊的」，查不到原因。

⚠ 改完請 commit 並推上 GitHub。直接在 Jetson 上改而不 commit，下一次 `git pull`
可能衝突，也沒有人知道線上跑的是哪個版本。

### 3.2 看網頁、看監控電腦

**網頁**：瀏覽器開 **http://mirdc-orin-nx:8000**（經 Tailscale；含操作功能，請小心
刪除類按鈕）。

**監控電腦本身**（選配，需 §4.2）：`ssh monitor` 進去是 Windows 命令列，可看 CSV
資料夾、上傳程式的 `edge_backend\uploader.log`。

### 3.3 從 Jetson 取監控電腦的 CSV

Jetson 上已設好 `monitor` 這個別名（使用 Jetson 專屬金鑰）：

```bash
scp -O -T "monitor:\"C:/<資料夾>/BTP_Sensor_log-2026-03-27.csv\"" /tmp/
```

`-O -T` 是必要的：sftp 目前在 Windows 端起不來（§6），`-O` 改用舊式 scp；
路徑含空格時要加引號，而引號會讓 scp 的檔名檢查誤判，`-T` 關掉那個檢查。

## 4. 管理者

### 4.1 加一位工程師

1. Tailscale 管理頁（login.tailscale.com/admin）→ Users → Invite。
2. 把他的公鑰加到 **Jetson**：
   ```bash
   ssh jetson 'cat >> ~/.ssh/authorized_keys' < 他的公鑰.pub
   ```
3. 若他也要連監控電腦（且監控電腦已做 §4.2），把同一把公鑰加到**監控電腦**
   （以系統管理員身分）：
   ```powershell
   .\deploy\monitor_ssh_setup.ps1 -PubKeys 他的公鑰.pub
   ```
   （腳本可重複執行，不會重複加同一把鑰匙，也不會疊出第二份設定。）

**移除一位工程師**：在 Tailscale 管理頁移除他的使用者與裝置，並從 Jetson（與監控電腦）
的 authorized_keys 刪掉那一行。⚠ Tailscale 那一步**最要緊**：網頁 API 對整個 Tailscale
網段開放且沒有登入驗證（§1），只刪 SSH 金鑰的話，他仍然打得開網頁、用得了刪除功能。

定期看一次 Jetson 上有哪些金鑰：`ssh jetson 'ssh-keygen -lf ~/.ssh/authorized_keys'`，
每一行最後的註解標明是誰的；認不出來的就刪。

### 4.2 （選配）讓 Jetson 能 SSH 進監控電腦

架構 B 的主功能（上傳、網頁）**不需要這一步**。只在要遠端看監控電腦的檔案、記錄程式
狀態時才做，且要實驗室同意（需系統管理員、會裝 OpenSSH Server）。

1. 用另一台電腦下載 Win32-OpenSSH 的 MSI（github.com/PowerShell/Win32-OpenSSH/releases，
   2026-10-14 測試用 `OpenSSH-Win64-v9.8.3.0.msi`，Microsoft 簽章），連同
   Jetson 的公鑰（`~/.ssh/id_ed25519_monitor.pub`）用隨身碟帶過去。
2. 以系統管理員開 PowerShell：
   ```powershell
   .\deploy\monitor_ssh_setup.ps1 -JetsonIP 192.168.55.1 `
       -PubKeys jetson_monitor.pub,工程師1.pub -MsiPath D:\OpenSSH-Win64-v9.8.3.0.msi
   ```
3. 監控電腦 USB 那一側的 IP 不一定是 `192.168.55.100`（DHCP 給的），裝完在監控電腦上
   `ipconfig` 確認，再改 Jetson `~/.ssh/config` 裡 `monitor` 的 `HostName`，以及
   工程師設定裡的同一行。

還原：`.\deploy\monitor_ssh_setup.ps1 -Uninstall`（停用 sshd、移除防火牆規則）。

### 4.3 Jetson 上做過的設定

| 項目 | 位置 |
|---|---|
| Tailscale | 主機名 `mirdc-orin-nx`，`--accept-dns=false` |
| SSH：遠端只收金鑰，USB 直連保留密碼 | `/etc/ssh/sshd_config.d/50-reactor-remote.conf` |
| 防火牆：只放行 `l4tbr0`（USB）、`tailscale0`、`eno1`（有線） | `sudo ufw status verbose` |
| 免密碼重啟／查看 `reactor-compute`、`reactor-web` | `/etc/sudoers.d/reactor-compute` |
| 網頁 API 的來源限制、上傳通行碼 | `edge_backend/.env` 的 `REACTOR_ALLOW_NETS`、`REACTOR_INGEST_TOKEN` |
| 連監控電腦的金鑰與別名 | `~/.ssh/id_ed25519_monitor`、`~/.ssh/config` 的 `Host monitor` |

**Tailscale 金鑰到期**：預設 180 天要重新登入，到期即斷線而現場無人可處理。
管理頁 → Machines → `mirdc-orin-nx` →「…」→ **Disable key expiry**。

## 5. 出事時

**遠端連不上 Jetson**：到現場用 USB-C 接筆電，`ssh jetson@192.168.55.1`
（USB 直連可用密碼）。檢查 `tailscale status`、`nmcli con show --active`。

**改壞程式導致服務起不來**：
```bash
cd ~/Bioreactor-Edge-AI && git status && git diff      # 看改了什麼
git checkout -- <改壞的檔案或資料夾>                      # 還原
sudo systemctl restart reactor-compute reactor-web     # 不確定動到哪個就兩個都重啟
```
（`sudo systemctl restart` 一次帶兩個服務名稱不在免密碼清單裡，會問密碼；
分兩行各重啟一個就不會。）

**網頁打不開但 SSH 進得去**：`sudo systemctl status reactor-web`、
`sudo journalctl -u reactor-web -n 50`。資料不會掉：都還在監控電腦的 CSV 裡，
上傳程式會在 Jetson 恢復後自動補送。

**防火牆把自己鎖在外面**：USB 介面（`l4tbr0`）永遠放行，從 USB 進去修。

## 6. 已知問題

1. **網頁 API 沒有登入驗證，只靠來源網段把關。** 對 Tailscale 網段整段開放，所以
   Tailscale 網路裡的人＝能操作刪除功能的人（§4.1）。人數多起來或要給唯讀的人看時，
   應替 API 加登入或改成唯讀模式。
   附帶：架構 A 時期監控電腦上的後端曾聽在 0.0.0.0（2026-10-14 已改為只聽
   `REACTOR_HOST`，預設 127.0.0.1）。架構 B 中它只在 Jetson 故障、回退單機模式時才會
   跑，仍然只聽本機。
2. **sftp 起不來。** Windows 端 `sftp-server` 在 sshd 底下以代碼 1 結束（本機直接
   執行正常）。尚未查明，需開 sshd 除錯紀錄。影響：WinSCP、FileZilla 等用 sftp
   的工具無法瀏覽監控電腦；`scp -O -T` 與 `ssh monitor` 不受影響。
3. **Jetson 的時鐘沒有電池。** 斷網開機時時間會停在上次關機的時刻（10/14 實測慢
   25 小時），有網路後自動校正。感測資料的時間戳來自監控電腦寫的 CSV，不受影響；
   受影響的是 Jetson 自己產生的時間，例如模組結果的 `computed_at`。
4. **Jetson 目前的 Wi-Fi 設定是建置時所在地的網路**，帶到別處要重新設定
   （`nmcli dev wifi connect <SSID> password <密碼>`，需先用 USB 進去）。
5. Jetson 的 Tailscale 健康檢查有一則 `connmark` 警告（Tegra 核心缺 iptables
   模組），只影響子網路由／出口節點等進階功能，本架構沒有用到。
