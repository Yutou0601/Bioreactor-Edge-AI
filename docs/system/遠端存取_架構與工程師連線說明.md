# 遠端存取：架構與工程師連線說明

2026-10-14 建置並實測。給兩種人看：

- **工程師**：在家或任何地方，連 Jetson 改模組、連監控電腦看資料與網頁。看 §2、§3。
- **管理者**：加人、部署真正的監控電腦、出事時救回來。看 §4、§5。

密碼一律不寫在這份文件裡（repo 會上 GitHub），另行告知。

---

## 1. 架構

```
工程師電腦（任何地方）
   │  Tailscale（加密私網；不對公網開任何埠）
   ▼
Jetson Orin NX  mirdc-orin-nx        ← 唯一連外網的機器
   │  SSH 只收金鑰；防火牆只放行 USB／有線／Tailscale
   │  USB（192.168.55.x）或網路線
   ▼
監控電腦（Windows，不連外網）
   ├─ SSH：只收金鑰、只接受來自 Jetson 的連線（Windows 防火牆）
   └─ 網頁＋API：只聽 127.0.0.1:8000，**不對任何網路介面開放**
                 遠端要看 → 走 SSH 通道
```

**為什麼監控電腦只開 SSH、網頁不直接開出去**：後端 API 沒有登入驗證，而且有
刪除紀錄、刪除批次的端點。SSH 一個埠同時給了身分驗證、加密與轉發，網頁經它
的通道看即可，不必替 API 另做登入。

**為什麼不用 Windows 檔案分享（SMB）**：那是勒索病毒的主要傳播途徑，正是實驗室
顧慮的事。

### 實測結果（2026-10-14）

| 路徑 | 結果 |
|---|---|
| 工程師 → Jetson（Tailscale，金鑰） | ✓ |
| 工程師 → Jetson（密碼） | 拒絕（設計如此） |
| 從同一 Wi-Fi 內網直連 Jetson :22 / :8100 | 防火牆擋 |
| Jetson → 監控電腦 SSH（Jetson 專屬金鑰） | ✓ |
| 從 Wi-Fi 那一側連監控電腦 :22 | 防火牆擋 |
| 工程師 → Jetson → 監控電腦（SSH 跳板） | ✓ |
| 工程師看監控網頁（SSH 通道 → `localhost:18000`） | ✓ API 與首頁皆 200 |
| Jetson 直接打監控電腦 :8000 | 連不到（修正前是 **200**，見 §6） |
| 遠端改 Jetson 模組 → 重啟 → 由監控端觸發 → 跑到改過的版本 | ✓ |
| Jetson 從監控電腦取 CSV（`scp -O -T`） | ✓ |
| Jetson 以 sftp 瀏覽監控電腦 | ✗ 尚未解決，見 §6 |

⚠ 上表「工程師端」是在與 Jetson 同一個 Wi-Fi 的電腦上測的，Tailscale 走的是區網
直連。跨網際網路（真正在家）的情況要等 Jetson 回到實驗室後再測一次。

## 2. 工程師第一次設定

1. **安裝 Tailscale**（tailscale.com/download），用管理者邀請你的帳號登入。
2. **產生 SSH 金鑰**（已有就跳過），把**公鑰**（`.pub`）傳給管理者：
   ```
   ssh-keygen -t ed25519 -C "你的名字"
   ```
   ⚠ 只傳 `.pub`，私鑰永遠不離開你的電腦。
3. 管理者把公鑰加到 Jetson 和監控電腦後（§4.1），在你的 `~/.ssh/config` 加：
   ```
   Host jetson
       HostName mirdc-orin-nx
       User jetson
       ServerAliveInterval 30

   Host monitor
       HostName 192.168.55.100          # 監控電腦在 Jetson 那一側的位址
       User "<監控電腦的 Windows 帳號>"   # 帳號有空格要加引號
       ProxyJump jetson
       LocalForward 18000 127.0.0.1:8000
       ServerAliveInterval 30
   ```
4. 測試：`ssh jetson`、`ssh monitor` 都要能直接登入、不問密碼。

## 3. 日常操作

### 3.1 改 Jetson 上的模組

建議用 **VS Code ＋ Remote-SSH**：連 `jetson`，開資料夾
`/home/jetson/Bioreactor-Edge-AI/edge_backend/modules/`。

改完之後（這三個指令不需要 sudo 密碼）：

```bash
sudo systemctl restart reactor-compute           # 套用修改
sudo systemctl status reactor-compute            # 確認 active
sudo journalctl -u reactor-compute -n 50         # 看載入有沒有錯
curl -s localhost:8100/health                    # 三個模組都要是 ready
```

⚠ **改到 `module.json` 的 `result_columns`、或 `run.py` 的 `SCHEMA` 時，監控電腦
那份也要同步。** 結果表由監控電腦依它自己那份 `module.json` 建立；兩邊不一致時，
畫面只會顯示「結果是舊的」，查不到原因。改完請 commit，讓兩台走同一份程式。

⚠ 只改 `analysis.py` 的計算內容時，只要重啟 Jetson 的服務即可，監控電腦不必動。

### 3.2 看監控電腦

```bash
ssh -N monitor        # 開著這個視窗 = 通道開著
```
然後瀏覽器開 **http://localhost:18000**，就是監控電腦的網頁（含操作功能，
等同坐在監控電腦前面——請小心刪除類按鈕）。

登入監控電腦本身（看檔案、查服務）：`ssh monitor`（進去是 Windows 命令列）。

### 3.3 從 Jetson 取監控電腦的 CSV

Jetson 上已設好 `monitor` 這個別名（使用 Jetson 專屬金鑰）：

```bash
scp -O -T "monitor:\"C:/<資料夾>/BTP_Sensor_log-2026-03-27.csv\"" /tmp/
```

`-O -T` 是必要的：sftp 目前在 Windows 端起不來（§6），`-O` 改用舊式 scp；
路徑含空格時要加引號，而引號會讓 scp 的檔名檢查誤判，`-T` 關掉那個檢查。

## 4. 管理者

### 4.1 加一位工程師

1. Tailscale 管理頁（login.tailscale.com/admin）→ Users → Invite。
2. 把他的公鑰加到 **Jetson**：
   ```bash
   ssh jetson 'cat >> ~/.ssh/authorized_keys' < 他的公鑰.pub
   ```
3. 若他也要連監控電腦，把同一把公鑰加到**監控電腦**（以系統管理員身分）：
   ```powershell
   .\deploy\monitor_ssh_setup.ps1 -PubKeys 他的公鑰.pub
   ```
   （腳本可重複執行，不會重複加同一把鑰匙，也不會疊出第二份設定。）

移除一位工程師：從兩邊的 authorized_keys 刪掉那一行，並在 Tailscale 管理頁移除。

### 4.2 部署到真正的監控電腦（離線）

1. 用另一台電腦下載 Win32-OpenSSH 的 MSI（github.com/PowerShell/Win32-OpenSSH/releases，
   2026-10-14 測試用 `OpenSSH-Win64-v9.8.3.0.msi`，Microsoft 簽章），連同
   Jetson 的公鑰（`~/.ssh/id_ed25519_monitor.pub`）用隨身碟帶過去。
2. 以系統管理員開 PowerShell：
   ```powershell
   .\deploy\monitor_ssh_setup.ps1 -JetsonIP <Jetson 在監控電腦那一側的 IP> `
       -PubKeys jetson_monitor.pub,工程師1.pub -MsiPath D:\OpenSSH-Win64-v9.8.3.0.msi
   ```
3. 監控電腦的 `edge_backend` 要是 2026-10-14 之後的版本（後端只聽 127.0.0.1，§6）。
4. 若連接方式不是 USB，修改 Jetson `~/.ssh/config` 裡 `monitor` 的 `HostName`，
   以及工程師設定裡的同一行。

還原：`.\deploy\monitor_ssh_setup.ps1 -Uninstall`（停用 sshd、移除防火牆規則）。

### 4.3 Jetson 上做過的設定

| 項目 | 位置 |
|---|---|
| Tailscale | 主機名 `mirdc-orin-nx`，`--accept-dns=false` |
| SSH：遠端只收金鑰，USB 直連保留密碼 | `/etc/ssh/sshd_config.d/50-reactor-remote.conf` |
| 防火牆：只放行 `l4tbr0`（USB）、`tailscale0`、`eno1`（有線） | `sudo ufw status verbose` |
| 免密碼重啟／查看運算服務 | `/etc/sudoers.d/reactor-compute` |
| 連監控電腦的金鑰與別名 | `~/.ssh/id_ed25519_monitor`、`~/.ssh/config` 的 `Host monitor` |

**Tailscale 金鑰到期**：預設 180 天要重新登入，到期即斷線而現場無人可處理。
管理頁 → Machines → `mirdc-orin-nx` →「…」→ **Disable key expiry**。

## 5. 出事時

**遠端連不上 Jetson**：到現場用 USB-C 接筆電，`ssh jetson@192.168.55.1`
（USB 直連可用密碼）。檢查 `tailscale status`、`nmcli con show --active`。

**改壞模組導致服務起不來**：
```bash
cd ~/Bioreactor-Edge-AI && git status && git diff      # 看改了什麼
git checkout -- edge_backend/modules/<模組>/            # 還原
sudo systemctl restart reactor-compute
```

**防火牆把自己鎖在外面**：USB 介面（`l4tbr0`）永遠放行，從 USB 進去修。

## 6. 已知問題

1. **監控後端原本聽在 0.0.0.0（已修正，2026-10-14）。** `main.py` 與
   `launcher.pyw` 寫死了 `0.0.0.0`，`.env` 的 `REACTOR_HOST` 只被拿來組網址、
   沒有被用來綁定。實測 Jetson 可以不經 SSH 直接呼叫監控電腦沒有驗證的 API
   （HTTP 200），而 Windows 防火牆裡有人按過的 `python.exe` 允許規則讓它通過。
   已改為只聽 `REACTOR_HOST`（預設 127.0.0.1）。**監控電腦更新到此版本之前，
   不要把它接到 Jetson。**
2. **sftp 起不來。** Windows 端 `sftp-server` 在 sshd 底下以代碼 1 結束（本機直接
   執行正常）。尚未查明，需開 sshd 除錯紀錄。影響：WinSCP、FileZilla 等用 sftp
   的工具無法瀏覽監控電腦；`scp -O -T` 與 `ssh monitor` 不受影響。
3. **Jetson 的時鐘沒有電池。** 斷網開機時時間會停在上次關機的時刻（10/14 實測慢
   25 小時），有網路後自動校正。遠端模式下模組結果的 `computed_at` 由 Jetson 產生，
   會受影響。
4. **Jetson 目前的 Wi-Fi 設定是建置時所在地的網路**，帶到別處要重新設定
   （`nmcli dev wifi connect <SSID> password <密碼>`，需先用 USB 進去）。
5. Jetson 的 Tailscale 健康檢查有一則 `connmark` 警告（Tegra 核心缺 iptables
   模組），只影響子網路由／出口節點等進階功能，本架構沒有用到。
