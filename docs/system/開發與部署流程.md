# 開發與部署流程

2026-09-03 建立。

## 為什麼不用 Docker

先講結論：**監控電腦上不要 Docker。**

一開始我以為決定性理由是序列埠（Docker Desktop 在 Windows 上跑 WSL2 容器，
拿不到 COM 埠）。但現場的流程是**記錄程式自己開埠寫 CSV，本系統只做 CSV
分析**，所以那條理由不成立。

真正剩下的理由是兩個：

1. **監控電腦只有 4 GB，應用預算 60 MB。** Docker Desktop + WSL2 待機就是
   GB 級開銷。（未實測，經驗值。）
2. **研究員要一鍵啟動。** 多一層「Docker Desktop 要開著、WSL2 要健康」。

而 Docker 能解的問題（模組相依隔離、記憶體跑完就還），**子行程也能解**，
代價小三個數量級。見架構文件的跨行程模組設計。

**什麼時候 Docker 才合理**：如果之後把分析搬到另一台伺服器，那台可以容器化。
它沒有 4 GB 限制，而且「換台機器裝得起來」在那裡才是真需求。

## 三層分離（這是整套流程的基礎）

| 層 | 內容 | 進版控？ |
|---|---|---|
| **程式** | `.py`、`web_frontend/dist/` | ✔ 進 |
| **設定** | 資料夾路徑、埠號 | ✘ `.env` 不進；範本 `.env.example` 進 |
| **資料** | `reactor.db`、`experiment_runs.json`、log | ✘ **絕對不進** |

### ⚠ 這一層以前是壞的

`reactor.db` 原本**既沒被追蹤也沒被 ignore**。意思是：

- `git status` 永遠顯示它
- 有人 `git add .` 就把現場資料傳上 GitHub
- **`git clean -fdx` 會直接刪掉整個正式資料庫**

2026-09-03 補進 `.gitignore`。`server.log`、`*.log` 同樣。

### ⚠ dist/ 刻意不 ignore

一般不建議把建置產物進版控，但這裡**必須**：監控電腦沒有 node/npm，
`git pull` 拿不到建置好的前端就只有後端，打開網頁是 404。
體積約 1.3 MB，只在前端有改時才變動。

### calibration.json 是例外，要進版控

它是離線校準模組產出的常數，決定 `rb` 欄的值。必須與程式碼一起版本化，
否則同一份資料在兩台機器會算出不同結果，而且事後查不出用的是哪一版。

## 發布（在筆電上）

```
release.bat v1.3.0
```

五個步驟，**任何一步失敗就不發布**：

1. 檢查工作區乾淨 —— 發布必須對應一個回得去的 commit
2. `npm run build`
3. **`system_test.py` 34 項全過** ← 這個門檻是整支腳本的意義
4. 把 `dist/` 提交
5. 打 tag、推上去

> ⚠ 第 3 步不可以拿掉。現場跑一個壞版本的代價，遠大於這裡建置失敗。

## 更新（在監控電腦上）

```
update.bat
```

設計上**不會弄丟東西**：

- 現場資料碰不到（都 gitignore 了）
- **偵測到有人在這台機器改過檔案就停下來**，而不是默默覆蓋掉
- 印出前一版 commit，回滾就是 `git reset --hard <那個 commit>`
- 沒有 `.env` 時自動從範本複製，並提醒去確認路徑
- 拉完做一次 import 自我檢查

## 設定怎麼走

`edge_backend/core/config.py`，優先序：

```
環境變數  >  edge_backend/.env  >  內建預設
```

⚠ **不用 python-dotenv** —— 為了讀 `KEY=VALUE` 加一個相依，在 60 MB 預算下
不划算。20 行標準庫就夠。

啟動時會把整份設定印出來。「指到錯的資料夾」是最容易發生又最難察覺的部署
錯誤——2026-07-22 記錄靜默中斷 17.5 小時無人發現，設定印在啟動訊息裡，
至少這類錯會當場看見。

| 變數 | 預設 | 說明 |
|---|---|---|
| `REACTOR_DATA_DIR` | `C:\Users\BTP\Desktop\data` | 記錄程式寫 CSV 的資料夾 |
| `REACTOR_HOST` / `REACTOR_PORT` | `127.0.0.1` / `8000` | 後端位址 |
| `REACTOR_DB` | 空＝`edge_backend/reactor.db` | 循環資料庫 |
| `REACTOR_ENABLE_LSTM` | `0` | ⚠ 開了會讓 CSV 匯入把 torch 拉進常駐行程（RSS 62→348 MB），而該預測前端不顯示 |
| `REACTOR_POLL_SECONDS` | `60` | csv_watcher 檢查間隔 |

## 兩條管道：git 與 pack

現場的狀況是「**網路可以開，但平常是關的**；Python 與 venv 已經裝好」。
所以：

| 情況 | 用哪個 | 為什麼 |
|---|---|---|
| **平常更新** | **git**（`update.bat`） | 開網路 → 更新 → 關網路。只傳改動，回滾一行指令，看得到改了什麼 |
| 網路臨時開不了、或**裝新機器** | **pack**（`pack.bat` → `install.bat`） | 整包帶著走，連 wheel 都在裡面，完全離線可裝 |

**不要選 PyInstaller 單一 exe。** 三個理由：

1. **它不省記憶體** —— frozen exe 的 RSS 跟直接跑一樣，打包的是同一份
   numpy/FastAPI。60 MB 預算一點都不會少。
2. **體積** —— numpy + FastAPI + uvicorn 就 60~90 MB；把 pandas/scipy 也包
   進去會到 250~400 MB，而且每次更新整包重下。
3. ⚠ **防毒誤判** —— PyInstaller 產物被企業防毒擋掉很常見，在研究單位的機器
   上尤其麻煩。而且現場看不到原始碼，出事時沒法叫人念錯誤訊息給你聽。

Python 已經裝好了，所以也不需要 embeddable Python。

### 打包（筆電）

```
pack.bat v1.3.0
```

會做：建置前端 → **34 項系統測試** → `pip download` 抓 wheel →
組出 `Bioreactor-v1.3.0.zip`。

⚠ **打包這一步需要網路**（要抓 wheel），但**產出的包完全離線可裝**。

⚠ **絕不打包進去**：`reactor.db`、`experiment_runs.json`、`.env`、`venv`、
`Testing_data`、`__pycache__`。那些是現場資料或機器專屬，塞進去會覆蓋掉
現場自己的狀態。

### 安裝（監控電腦）

解壓，執行 `install.bat`。順序是：

```
venv → 相依（優先用內附 wheel，離線也裝得起來）→ 設定 → 自我檢查 → 啟動
```

## 自我檢查（`edge_backend/selfcheck.py`）

`install.bat` 和 `update.bat` 都會在啟動前跑它。**沒過就不啟動。**

> ⚠ 啟動一個設定錯的服務，比不啟動更糟：網頁會正常打開、一切看起來正常、
> 只是永遠沒有資料進來。2026-07-22 記錄靜默中斷 17.5 小時無人發現就是這樣。

它與 `system_test.py` 的分工：

| | 跑在哪 | 驗什麼 | 需要測試資料 | 耗時 |
|---|---|---|---|---|
| `system_test.py` | 開發筆電 | 程式對不對（35 項） | 要 | 幾分鐘 |
| `selfcheck.py` | 現場機器 | 這台裝好了沒（11 項） | 不要 | 幾秒 |

檢查項目：Python 版本、fastapi/uvicorn/numpy、`dist/index.html`、
**資料夾路徑存不存在**、資料庫可讀寫、埠有沒有被占用、核心相依乾不乾淨。

⚠ **「資料夾路徑」是裡面最重要的一項**，也是唯一會擋下啟動的設定類檢查。
其餘如「沒有 `.env`」「埠已被占用」只警告不擋——後者通常代表已經有一份在
跑，那不是錯誤，但要講出來，否則會有人開第二份然後納悶設定為什麼沒生效。

⚠ selfcheck 自己不可以載入 torch/pandas。它跑在 60 MB 預算的機器上，
而且它的工作就是確認核心夠瘦——自己胖了就沒有意義。

`release.bat` 第 1 步會直接擋下來——而那是對的，發布必須對應一個明確的
commit。但這代表**在能發第一版之前，得先把這堆整理掉**。

那 274 個大多是論文的分析腳本（`rb_*.py`、`fig_*.py`、`tau_*.py` 等）。
它們該不該進版控是你的決定，不是我能替你決定的：

- 進版控 → 分析可重現，但 repo 變大、監控電腦也會拉到用不到的腳本
- 另開一個 `analysis/` 資料夾並 ignore → 監控電腦乾淨，但分析不可重現

我的建議是**進版控**（分析可重現對論文很重要），但放進 `edge_backend/analysis/`
子資料夾，讓「常駐程式」與「離線分析」在目錄結構上就分得開。
