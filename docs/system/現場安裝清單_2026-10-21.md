# 現場安裝清單（2026-10-21，金屬中心）

給明天到現場安裝的人看：照順序打勾即可。每一步「看到什麼才算過」都寫了。
細節與原因見 [監控電腦部署流程_架構B_2026-10-16.md](監控電腦部署流程_架構B_2026-10-16.md)。

密碼、通行碼一律不寫在這份文件裡（repo 在 GitHub 上）；通行碼在隨身碟安裝包
`BTP_install_kit_2026-10-21\ingest_token.txt`，Jetson 登入密碼另行告知。

**最快的路**：Jetson 接好（第 2 節）→ 監控電腦插隨身碟、雙擊 `ONE_CLICK_INSTALL.bat`（第 3.0 節）
→ 驗收（第 3.6 節）。第 3.2～3.5 節是一鍵安裝自動做掉的事，失敗時才照手動做。

**做完之後的樣子**：

```
設備 ─COM4─▶ 廠商記錄程式（不動）─▶ CSV ─▶ 上傳程式 ─USB-C─▶ Jetson（後端＋資料庫＋網頁）
                                                              │ Wi-Fi／網路線
                                                              ▼
                                                  Tailscale ─▶ 家裡、工程師遠端
```

- [ ] Jetson 要連哪個網路（只有 Jetson 連外網，給遠端維護用）？Wi-Fi 名稱與密碼，或可用的網路孔。

## 2. Jetson

1. [ ] 接電，**等 2 分鐘**開機完成。
2. [ ] USB-C 接到**監控電腦**。
3. [ ] 讓 Jetson 連上實驗室網路（二選一）：
   - **Wi-Fi**：在監控電腦開「命令提示字元」：
     ```
     ssh jetson@192.168.55.1
     nmcli dev wifi connect "<Wi-Fi 名稱>" password "<Wi-Fi 密碼>"
     ```
     （USB 直連可用密碼登入；遠端只收金鑰。Jetson 身上已有 PDCN、57-8n-2.4G、RT-N18U 等
     舊設定檔，若其中之一就是實驗室的網路，可能已自動連上——用 `nmcli con show --active` 確認。）
   - **網路線**：插 Jetson 的網路孔即可（防火牆已放行 `eno1`）。
4. [ ] 確認上線：還在 ssh 裡執行
   ```
   ping -c 3 8.8.8.8
   tailscale status | head -3
   systemctl is-active reactor-web reactor-compute
   ```
   **看到**：ping 有回應；`mirdc-orin-nx` 那一行不是 offline；兩個服務都是 `active`。
5. [ ] `exit` 離開 ssh。

## 3. 監控電腦

### 3.0 一鍵安裝（建議）

先做完 3.1（看現況）與 3.3（接線確認）；若實驗室同意，**暫時開網路**讓它 git pull。

1. [ ] 插隨身碟，先預覽（什麼都不改）：在隨身碟資料夾的網址列輸入 `cmd` 按 Enter，執行
   ```
   ONE_CLICK_INSTALL.bat -DryRun
   ```
   **看到**：`project:` 是監控電腦上的專案資料夾；CSV 資料夾那行標著 **LIVE**（記錄程式正在寫）；
   `from USB kit ingest_token.txt (32 chars)`。
2. [ ] 沒問題就雙擊 `ONE_CLICK_INSTALL.bat`。它依序：找專案資料夾 → git pull（有修改先 stash；
   沒網路就用隨身碟 `offline_files\` 覆蓋，舊檔先備份）→ 找出記錄程式**正在寫**的 CSV 資料夾
   （會問一次確認）→ 從隨身碟讀通行碼 → 以 UTF-8 寫入 `.env` → 把舊版開機自動啟動移到桌面
   備份資料夾 → 執行 `monitor_uploader_setup.bat`（七步，最後要按任意鍵）→ 開主控台。
3. [ ] 做完**關掉監控電腦的網路**，跳到 3.6 驗收。

⚠ 為什麼用一鍵安裝而不直接雙擊 setup.bat：CSV 資料夾路徑若含中文，setup.bat 用 cmd 寫進
`.env` 的是 ANSI 編碼、Python 讀成亂碼，上傳程式找不到資料夾——而 setup.bat 自己的檢查會照樣通過。
一鍵安裝改以 UTF-8 寫入、並以 UTF-8 字碼頁執行 setup.bat（2026-10-20 以含中文的路徑實測通過）。

### 3.1 先看現況，什麼都不改

- [ ] 舊版（架構 A）有沒有在跑：工作管理員找 `python`／`pythonw`；

### 3.2 更新程式碼（二選一）

**A. 暫時開網路、用 git（建議）**

```
cd <專案資料夾>
git status
git pull --ff-only origin main
```

- `git status` 若列出被修改的檔案：先 `git stash`，再 pull。（`.env`、資料庫、上傳進度不受影響——它們不進 git。）
- **看到**：`git log --oneline -1` 是 2026-10-21 當天或之後的版本，且資料夾裡有這份清單。
- ⚠ **不要用 `update.bat`**：它最後會啟動 `START.bat`，那是舊架構的整套後端。
- [ ] 做完**立刻關掉監控電腦的網路**。

**B. 不能開網路**：把隨身碟 `offline_files\` 裡的檔案，依相同資料夾結構覆蓋到專案資料夾
（一鍵安裝在沒網路時會自動這樣做）。

## 5. （選配）讓 Jetson 能取監控電腦的檔案

只有實驗室同意才做；需要系統管理員。隨身碟 `optional_ssh\` 裡有 OpenSSH 安裝檔與 Jetson 的公鑰。

```powershell
# 系統管理員 PowerShell
.\deploy\monitor_ssh_setup.ps1 -JetsonIP 192.168.55.1 `
    -PubKeys <隨身碟>\optional_ssh\jetson_monitor.pub -MsiPath <隨身碟>\optional_ssh\OpenSSH-Win64-v9.8.3.0.msi
```

步驟與說明見 [遠端存取_架構與工程師連線說明.md](遠端存取_架構與工程師連線說明.md) §4.2。

## 7. 出問題時

| 現象 | 處理 |
|---|---|
| `[3/7]` ping 不到 | 換 USB-C 口；等 2 分鐘；`ncpa.cpl` 看有沒有新網卡 |
| `HTTP 401` | 通行碼錯：改 `edge_backend\.env` 的 `REACTOR_INGEST_TOKEN`，重跑 setup |
| `HTTP 403 … REACTOR_ALLOW_NETS` | 請求不是從 USB 來：確認 `REACTOR_UPLOAD_URL=http://192.168.55.1:8000` |
| `No BTP_Sensor_log-*.csv` | 資料夾填錯：改 `.env` 的 `REACTOR_DATA_DIR`，重跑 |
| Jetson 連不上網 | `ssh jetson@192.168.55.1` 進去：`nmcli con show --active`、`tailscale status` |
| Jetson 整台壞了 | 資料都在 CSV；雙擊舊版 `START.bat` 回單機模式；修好後上傳程式自動補送 |

**還原**：雙擊 `deploy\monitor_uploader_remove.bat`（停掉上傳程式、移除捷徑；設定與上傳進度保留）。
