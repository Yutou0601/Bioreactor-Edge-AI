# 監控電腦部署流程（架構 B）

2026-10-16。給要到金屬中心、把監控電腦接上 Jetson 的人看。照順序做，每一步都有「看到什麼才算過」。

通行碼、密碼一律不寫在這份文件裡（repo 在 GitHub 上），另外用紙本或隨身碟帶。

---

## 0. 做完之後長什麼樣

```
設備 ─COM4─▶ 廠商記錄程式（不動它）─▶ CSV 資料夾
                                          │  monitor_uploader：只讀檔、只送新增的行
                                          ▼  USB-C（192.168.55.x，點對點）
                                   Jetson Orin NX
                                   ├─ 後端＋資料庫＋分析
                                   └─ 網頁 http://192.168.55.1:8000
                                          ▲
監控電腦的瀏覽器 ──────────────────────────┘
```

**監控電腦上多出來的東西只有三樣**：一支 Python 程式（只用標準函式庫，常駐約 25 MB）、
「啟動」資料夾裡一個捷徑、桌面上一個網頁連結。

**給實驗室的安全說明**（他們擔心中毒，這幾點可以直接講）：

| 項目 | 狀態 |
|---|---|
| 需要系統管理員權限 | 不需要 |
| 安裝 Windows 服務 | 沒有 |
| 監控電腦開放任何入站連接埠 | 沒有（上傳程式只往外連 Jetson） |
| 打開 COM 埠 | 絕不（記錄程式獨占 COM4，我們只讀它寫出的檔案） |
| 監控電腦需要開 Wi-Fi／連外網 | 不需要 |
| USB 線會不會變成上網通道 | 不會：Jetson 防火牆擋轉送、也沒有對 USB 網段做 NAT（2026-10-16 已在 Jetson 上確認），現場第 3 步再驗一次 |
| 能不能還原 | 一個指令（第 9 節），設定與資料都不動 |

## 1. 出發前

### 1.1 Jetson 端（2026-10-16 已遠端確認，出發前再看一次即可）

```bash
ssh jetson
systemctl is-enabled reactor-web reactor-compute tailscaled   # 三個都要 enabled
grep -c '^REACTOR_INGEST_TOKEN=.' ~/Bioreactor-Edge-AI/edge_backend/.env   # 要是 1
grep '^REACTOR_ALLOW_NETS=' ~/Bioreactor-Edge-AI/edge_backend/.env         # 要含 192.168.55.0/24
```

### 1.2 要帶的東西

- [ ] Jetson 本體＋電源
- [ ] **USB-C 線**：接 Jetson 的 device-mode 那個 USB-C 口（就是在筆電上測試時用的那個）
- [ ] **通行碼**（Jetson `.env` 裡 `REACTOR_INGEST_TOKEN` 的值）：紙本或隨身碟
- [ ] 隨身碟，內含下面五個檔（若現場不能開 Wi-Fi 做 git pull）：
  ```
  deploy\monitor_uploader_setup.bat
  deploy\monitor_uploader_remove.bat

  edge_backend\core\config.py
  ```
- [ ] （選配，第 8 節）OpenSSH 安裝檔與 Jetson 的公鑰

### 1.3 先問實驗室

- 同意用 USB-C 把 Jetson 接到監控電腦嗎？
- Jetson 在實驗室要連哪個 Wi-Fi（只有 Jetson 連外網，給遠端維護用）？
- （選配）同意在監控電腦裝 SSH 讓 Jetson 取檔嗎？不同意就跳過第 8 節，不影響主功能。

## 3. 接線

1. Jetson 接電，**等 2 分鐘**開機完成。
2. USB-C 接到監控電腦。
3. Win+R → `ncpa.cpl`：會多出一張網路卡（名稱可能是 RNDIS 或 USB Ethernet）。
4. 命令提示字元：
   ```
   ping 192.168.55.1          ← 要有回應
   ping 8.8.8.8               ← 監控電腦 Wi-Fi 關著時要「失敗」（證明 USB 不會變成上網通道）
   ```

Windows 第一次看到這張網卡時若跳出「網路類型」詢問，選**公用**（或直接關掉，預設就是公用）。
公用設定檔下，監控電腦對這張網卡的入站連線全擋，不需要另外設防火牆。

## 5. 執行安裝（一般使用者身分，不要用系統管理員）

雙擊 `deploy\monitor_uploader_setup.bat`。第一次會問兩件事：

- **CSV 資料夾**：第 2 步記下的路徑（含空格沒關係，不要加引號）
- **通行碼**：帶來的那串

若原本已有 `edge_backend\.env`（舊架構留下的），裡面已有的設定會保留，只補缺的。

**看到這七行全部出現才算過**（2026-10-16 在筆電上實測的輸出）：

```
[1/7] python   ...python.exe
[2/7] settings ...\edge_backend\.env
      N CSV files in <資料夾>
[3/7] USB link 192.168.55.1 reachable
[4/7] test upload ...
      送出 xxxx 行
[5/7] reconcile ...
      對帳完成：全部相符          ← 今天那一天不符是正常的（還在寫）
[6/7] autostart at logon: ...\Startup\Bioreactor uploader.lnk
[7/7] desktop shortcut ...\Bioreactor monitor.url
```

第一次會把資料夾裡**所有歷史 CSV** 都送上去，一年份約幾分鐘。之後只送新增的行。
任何一步失敗都會停下來並說明原因，**不會**裝上自動啟動。

## 6. 停用舊版的自動啟動（若第 2 步看到有）

舊架構的 `START.bat` 會在監控電腦上再跑一整套後端，和 Jetson 重複，還吃記憶體。

- 把「啟動」資料夾裡舊版的捷徑**移到桌面上的一個資料夾**（不要刪）。
- 舊版程式本身留著：**Jetson 壞掉時的備援**——雙擊 `START.bat` 就回到單機模式，
  瀏覽器開 `http://127.0.0.1:8000`。

## 7. 驗收

- [ ] 桌面「Bioreactor monitor」打開，即時頁**最新時間＝CSV 最後一行的時間**（差 1～2 分鐘內）
- [ ] 系統頁看得到 Jetson 溫度、電壓
- [ ] **登出再登入**（或重開機）後：工作管理員 → 詳細資料，有一個 `pythonw.exe` 約 25 MB；

- [ ] **拔 USB 5 分鐘再插回**：log 會出現「連不到…秒後重試」，插回後自動補送；再跑一次
      ```

      ```
      仍然全部相符 → 斷線期間資料沒有掉（資料一直在 CSV 裡，晚送而已）

## 8. （選配）讓 Jetson 能取監控電腦的檔案

只有實驗室同意才做。需要系統管理員、OpenSSH 安裝檔（離線）與 Jetson 的公鑰。
步驟見 `docs/system/遠端存取_架構與工程師連線說明.md` §4.2；腳本 `deploy\monitor_ssh_setup.ps1`
只開 SSH、只收金鑰、只接受來自 Jetson 的連線。不做這步，主功能完全不受影響。

另外，Jetson 在實驗室連上 Wi-Fi 後，到 Tailscale 管理頁把 `mirdc-orin-nx` 設成
**Disable key expiry**（否則 180 天後斷線，現場沒人能處理）。

## 9. 出問題時

| 現象 | 原因 | 處理 |
|---|---|---|
| `[3/7]` ping 不到 | 線接錯口／Jetson 還沒開機完／網卡沒出現 | 換 USB-C 口；等 2 分鐘；`ncpa.cpl` 看有沒有新網卡 |
| `HTTP 401` 或 token 錯誤 | 通行碼與 Jetson 不同 | 改 `edge_backend\.env` 的 `REACTOR_INGEST_TOKEN`，重跑 setup |
| `HTTP 403 … REACTOR_ALLOW_NETS` | 請求不是從 USB 來的 | 確認 `REACTOR_UPLOAD_URL=http://192.168.55.1:8000` |
| `No BTP_Sensor_log-*.csv` | 資料夾填錯 | 改 `.env` 的 `REACTOR_DATA_DIR`，重跑 |
| 網頁打不開 | USB 斷了或 Jetson 沒開 | 先 `ping 192.168.55.1` |
| 網頁有開但資料停了 | 上傳程式沒在跑 | 看 `edge_backend\uploader.log` 最後幾行；雙擊「啟動」資料夾的捷徑可手動啟動 |
| Jetson 整台壞了 | — | 資料都還在 CSV；先雙擊舊版 `START.bat` 回單機模式；Jetson 修好後上傳程式會自動補送 |

**還原**：雙擊 `deploy\monitor_uploader_remove.bat`。會停掉上傳程式、移除兩個捷徑；
`.env`、上傳進度（`.uploader_state.json`）與 log 保留，之後重裝會從中斷處接著送，不會重送全部。
